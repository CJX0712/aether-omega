# AETHER-Ω 架构详解

> 本文回答两个问题：**每一处设计为什么这样选**，以及**它的数学是什么**。
> 所有选型都来自 2026 年已公开的旗舰开源模型技术报告，没有一处是"我觉得这样更好"。

## 0. 全局视图

```

      │
```

## 1. 残差与归一化：为什么一定是 Pre-Norm + RMSNorm

### 1.1 Pre-Norm 的数学理由

Pre-Norm 下第 L 层输出可以展开为：

```
x_L = x_0 + Σ_{l=1}^{L} f_l( norm(x_{l-1}) )
```

关键性质：梯度回传到 `x_0` 有一条**不经过任何权重矩阵的直通路径**：

```
∂x_L / ∂x_0 = I + Σ_l (∂f_l/∂x_0)
                └─ 恒等项，永不消失
```

因此极深网络也能稳定训练。Post-Norm 没有这条保底通路，
梯度必须穿过每一层的权重矩阵，深度一上来就会退化——
这正是早期 Transformer 必须用 warmup 小心翼翼伺候的根因。

2026 年全系（Llama / Qwen / DeepSeek / Kimi / Gemma / gpt-oss）无一例外使用 Pre-Norm。

### 1.2 RMSNorm：为什么 LayerNorm 已经退场

```
RMS(x) = sqrt( (1/d)·Σ x_i² + ε )
out    = (x / RMS(x)) ⊙ g
```

与 LayerNorm 的差别：**不去均值（无 μ）、不平移（无 β）**，只做重缩放。

这带来一个关键的代数性质——**尺度不变（0-齐次）**：

```
RMSNorm(αx) = αx / (|α|·RMS(x)) · g = sign(α) · RMSNorm(x)
```

（严格说有限 ε 下不精确成立：`sqrt(α²ms + ε) ≠ α·sqrt(ms + ε)`，
偏差量级 `O(ε)`，实测 4.6e-6。ε→0 时严格成立。由 INVAR-09 / JS-06 交叉验证。）

**后果**：输出范数恒为 `O(√d)`，与输入尺度无关 ⇒ 残差流的范数不会随深度指数增长。
LayerNorm 因为减去了均值，破坏了这条性质，在极深网络里更容易失控。

**数值注意事项（由 GRAD-01 证书抓出的真实 bug）**：
低精度输入（fp16/bf16）必须提升到 fp32 做规约——`Σx²` 在 fp16 下极易溢出
（fp16 上界仅 65504，`(2^8)² × 512` 就已越界）。
但**绝不能无条件 `.float()`**：那会把 fp64 静默降到 fp32，
让梯度检验残差从 1e-9 恶化到 1e-2，制造一批假的失败。

## 2. MLA：多头潜在注意力

### 2.1 动机

先看 KV cache 的账。设 `n_h` 头、每头 `d_h` 维、序列长 `L`：

| 方案 | 每 token 缓存量 | 128K 上下文（bf16） |
|---|---|---|
| MHA | `2 · n_h · d_h` | 极大 |
| GQA | `2 · n_kv · d_h` | 降到 1/4 ~ 1/8 |
| **MLA** | `d_c + d_h^R` | 与头数无关 |

GQA 的思路是"多个 query 头共用一组 KV 头"；MLA 走得更远——
**缓存的压根不是展开后的 K/V，而是一个低秩潜在向量**。

### 2.2 完整数学

对第 t 个 token 的隐状态 `h_t ∈ R^d`：

**Query 侧**（也做低秩压缩，减少训练期激活内存）：

```
c_t^Q = W^{DQ} h_t                        ∈ R^{d_c'}        （q_lora_rank）
q_t^C = W^{UQ} c_t^Q                      ∈ R^{n_h · d_h^{nope}}
q_t^R = RoPE( W^{QR} c_t^Q )              ∈ R^{n_h · d_h^{rope}}
q_t   = concat(q_t^C, q_t^R)
```

**KV 侧**（这是省内存的地方）：

```
c_t^{KV} = W^{DKV} h_t                    ∈ R^{d_c}          ← 缓存它
k_t^{R}  = RoPE( W^{KR} h_t )             ∈ R^{d_h^{rope}}   ← 缓存它（所有头共享）
k_t^{C}  = W^{UK} c_t^{KV}                ∈ R^{n_h · d_h^{nope}}  不必展开
v_t      = W^{UV} c_t^{KV}                ∈ R^{n_h · d_v}         不必展开
```

**注意力**：

```
o_t = softmax( q_t · k_tᵀ / √d ) · v_t
u_t = W^O o_t
```

### 2.3 解耦 RoPE：MLA 的关键难点

**陷阱**：如果直接把 RoPE 加到 `c^{KV}` 上，吸收技巧立刻失效——
RoPE 会在 `c^{KV}` 与 `W^{UK}` 之间插入一个位置相关的旋转矩阵，不可交换：

```
RoPE_m( W^{UK} c ) ≠ W^{UK} RoPE_m( c )
```

**DeepSeek 的解法**：把位置信息剥离出去，只让一小段独立的 `k^R` 携带位置，
主体 `k^C` 保持位置无关。这就是"解耦"的含义。

代价是 RoPE 只作用在 `d_h^{rope}` 维（通常 16~32）而非完整的 `d_h`，
但实测效果无损——因为相对位置信息本身是低维的。

### 2.4 吸收技巧（推理加速的核心）

**naive 路径**（显式展开，作黄金参照）：

```
k = concat(W^{UK} c^{KV}, k^R)      v = W^{UV} c^{KV}
o = softmax(q kᵀ / √d) v
```

**absorb 路径**（推理期高效形式）：

```
q̂ = q^C W^{UK}                             ∈ R^{d_c}     ← head 维消失
logit = q̂ · (c^{KV})ᵀ + q^R · (k^R)ᵀ
ctx  = softmax(logit) @ c^{KV}              ∈ R^{d_c}
o    = ctx · W^{UVᵀ}                        ∈ R^{n_h · d_v}
```

**严格推导**（这就是 EQUIV-01 证书机器检查的恒等式）：

```
q·kᵀ = q^C·(W^{UK}c)^ᵀ + q^R·(k^R)^ᵀ
     = (q^C W^{UK})·c^ᵀ + q^R·(k^R)^ᵀ            ← 结合律，W^{UK} 左移

Σ_t a_t v_t = Σ_t a_t W^{UV} c_t = W^{UV} (Σ_t a_t c_t)   ← 线性，W^{UV} 外移
```

两条路径**逐位相等**，差异只来自浮点结合律。实测相对误差 **3.07e-07**（EQUIV-01）。

⚠️ **常见坑**：`W^{UK}` 与 `W^{UV}` 的形状。吸收时 `q̂` 的维度必须是 `d_c`（KV 潜在维度），
不是 `n_h·d_h`。写反了模型不报错，只会静默学得慢——
**这正是"必须有等价性证书"的理由**。

### 2.5 MLA + QK-Norm 的冲突与本仓库的适配

标准 QK-Norm 作用在展开后的 `k^C = W^{UK} c^{KV}` 上。
但 **RMSNorm 是非线性的**（除以依赖数据的 RMS），无法吸收进 q 侧：

```
RMSNorm(k^C) = k^C / RMS(k^C)   其中 RMS 依赖 c^{KV}
⇒ (q^C W^{UK}) · c^ᵀ 这一形式不再成立
```

一旦这样做，"naive ≡ absorb" 就被破坏，而这条性质正是 MLA 推理加速的根基。

**本仓库的解法**：把 K 侧归一化下移到**潜在空间**：

```
q^C   → QKNorm(d_nope)      可吸收 ✓（q^C 显式算了）
c^{KV} → RMSNorm(d_c)        可吸收 ✓（归一化作用在缓存的那份向量上）
k^R   → RMSNorm(d_rope)     可吸收 ✓（k^R 直接参与点积）
```

数学上依然是对 key 范数的硬约束（`‖k‖` 由 `‖c^{KV}‖` 与 `‖k^R‖` 共同控制），
但吸收技巧继续严格成立。这是 MLA + QK-Norm 组合下唯一能同时保住"稳定"与"可吸收"的写法。

## 3. 局部 : 全局 = 3 : 1 混合注意力

每 4 层里 3 层用滑动窗口（`O(L·w)`）、1 层用全注意力（`O(L²)`）。

```
Layer 0  ████░░░░  local (w=128)
Layer 1  ████░░░░  local
Layer 2  ████░░░░  local
Layer 3  ████████  global      ← 每 4 层一次
```

采用者：Gemma 3、Qwen 3、Mistral Small 3.1。
直觉：大多数语言现象是局部的（语法、搭配），少数需要长程（共指、主题）。
用 1/4 的全注意力成本拿到大部分长程能力。

## 4. DeepSeekMoE

### 4.1 三个设计，各治一个病

| 设计 | 解决的问题 |
|---|---|
| **细粒度专家** | 同等激活参数下，专家数越多路由组合空间越大（`C(n,k)` 意义下），specialization 更充分 |
| **共享专家** | 承载"所有 token 都必须经过的通用变换"，路由专家不必浪费容量重复学公共知识 |
| **无辅助损失偏置路由** | aux loss 会**污染梯度**（与 LM 目标竞争）；改用不进梯度图的偏置做负载均衡 |

### 4.2 偏置路由的数学

```
s_i  = sigmoid( W_gate · x )_i          路由分数（进梯度）
ŝ_i  = s_i + b_i                        仅用于 top-k 挑选（不进梯度）
top-k = argtop_k(ŝ)
w_i  = s_i / Σ_{j∈top-k} s_j            权重用**未加偏置**的分数

每步后：b_i ← b_i + u · sign( ē_i − e_i )     过载降偏置，欠载升偏置
```

偏置更新是**纯函数式**的（只依赖当前 batch 的负载统计），不进梯度图，
因此不破坏位级确定性——这对 AETHER-Ω 的自证式目标至关重要。

### 4.3 一个被证书抓出来的真实 bug

`_update_bias` 最初在 `forward()` 里无条件执行。推理（`eval`）时若继续更新，
同一个 batch 第二次前向就会得到不同的路由结果，直接破坏两条性质：

- **EQUIV-03**：KV cache 增量解码 ≡ 全序列重算
- **INVAR-06**：因果性（未来 token 不影响过去）

修正：偏置只在 `self.training` 时更新。
这个 bug 不会让程序崩溃，只会让结果静默漂移——正是证书存在的意义。

## 5. SwiGLU

```
FFN(x) = ( SiLU(x·W_gate) ⊙ (x·W_up) ) · W_down
       其中 SiLU(v) = v·σ(v)
```

为什么赢了：

- 相比 ReLU FFN：门控机制让**信息通路可控**（门接近 0 时直接阻断），梯度路径更平滑
- 相比 GELU-GLU：SiLU 处处可微且无上界，没有 GELU 的近似误差
- 工程细节：`W_gate` 与 `W_up` 合并成一次 `[D → 2I]` 的 matmul，省一次 kernel 启动

参数量 `3·D·I`（gate/up/down 各一份），这也是 FFN 占 Transformer 参数大头的原因。

## 6. RoPE + YaRN

### 6.1 RoPE 的相对性（机器可验证的核心性质）

把每两维视为一个复数 `z = x_{2i} + i·x_{2i+1}`，旋转就是乘以 `e^{i·mθ_i}`：

```
θ_i = 1 / base^{2i/d}
```

**根本性质**（INVAR-02 证书）：

```
⟨ RoPE(q, m), RoPE(k, n) ⟩ = ⟨ RoPE(q, m−n), k ⟩
```

即注意力分数只依赖相对位移 `m−n`。实测残差 **4.4e-06**。
这条性质是 RoPE 能外推到训练长度之外的理论依据。

实现上用复数乘法而非构造 `d×d` 旋转矩阵，省 `O(d²)` 内存。

### 6.2 YaRN 外推

频率"长短分治"插值：低频段（长波）线性插值保位置分辨率，
高频段（短波）不插值保局部细节，中间用斜坡平滑过渡。
再乘一个注意力温度校正 `sqrt(1/log(s))` 补偿插值后注意力分布熵的变化。

### 6.3 一个被证书抓出来的真实 bug：增量解码的位置偏移

`apply_rope` 最初取 `cos[:L]`，即**本段内的相对位置**。
增量解码时每次只喂 1 个 token，于是每个新 token 都被当成位置 0，
**整段生成的位置编码全部塌缩**。

这是 KV cache 实现里最经典的静默错误：模型照样能说话，只是长程位置关系全错。
由 EQUIV-03 证书抓出，修正为按 `start_pos` 取绝对位置，
并在越界时**抛错**而非静默截断。

形状约定（严格，不做"智能猜测"）：

```
x      : [B, L, H, D] / [B, L, D] / [L, D]   —— 位置维恒为 dim=1（无 batch 时 dim=0）
cos/sin: [L, D // 2]
```

自动探测维度顺序是隐蔽 bug 的温床——本仓库一律不使用 `[B,H,L,D]` 写法。

## 7. MTP：多 token 预测

### 7.1 原理

标准 LM 在每个位置只预测下一个 token，监督信号"稠密但短视"。
MTP 额外挂若干轻量预测头，让第 t 个位置的表示去预测 `t+1+d`：

```
主头： h_t → logits(t+1)
MTP d：h_t → logits(t+1+d)     d = 1..D
```

两点价值，第二点常被忽略：

1. **训练信号增密**：一个位置同时被 D+1 个目标监督，样本效率提升
2. **表示前置**：迫使 `h_t` 提前编码"未来 d 步还需要的信息"，
   这被认为是 MTP 能改善长程推理与猜测解码接受率的根因

### 7.2 实现约束（严格遵守 DeepSeek-V3 的做法）

- MTP 头**共享主模型的 embedding 与 output head**，不引入独立词表
- 每个头先做**跨步融合**：`RMSNorm(h_t)` 与 `RMSNorm(emb(y_{t+d-1}))` 拼接后线性投影回 dim
- **因果链**：MTP_d 的输入依赖 MTP_{d-1} 的表示（顺序执行），不是各自独立

对齐关系（设序列长 L）：位置 t 用 `h_t`，teacher forcing 喂入真实 token `y_{t+d}`，
预测目标 `y_{t+d+1}`。为使下标合法需 `t + d + 1 ≤ L−1` ⇒ 可用位置数 `n = L − d − 1`。

### 7.3 推理期的用途

MTP 头天然就是**自投机解码（self-speculative decoding）的草稿模型**：
先用 MTP 头快速猜 D 个 token，再用主模型一次前向并行验证。
`MTPStack.draft()` 提供了这个接口。

## 9. 实现层面的性能取舍

### 9.1 用广播 matmul，不用 4D einsum

4D einsum 在 CPU 后端会插入 permute + reshape + 拷贝，实测比 matmul 慢数倍。
而 matmul 对 `[B,H,L,d] @ [1,H,d,d']` 的 batch 维广播是**零拷贝**的：

```python
# 慢
q_hat = torch.einsum("blhd,hdc->blhc", q_c, w_uk)
# 快（数学等价）
q_hat = torch.matmul(q_c.transpose(1, 2), w_uk.unsqueeze(0))
```

实测前向提速约 1.3×。

### 9.2 CPU 线程数不是越多越好

16 核机器上实测（nano 档，8×256 前向）：

| threads | 1 | 2 | 4 | 6 | 8 | 16 |
|---|---|---|---|---|---|---|
| 耗时 (ms) | 2143 | 1526 | 1274 | **1243** | 1195 | 3072 |

（seq=512；seq=256 时 6 线程同样最优）

过多线程会在大量小矩阵上产生调度与缓存争用。
本仓库默认 `threads=6`，并提供 `scripts/benchmark.py --scan-threads` 让用户自行校准。

> ⚠️ 这个结论**不可外推到 GPU**——GPU 上的瓶颈（显存带宽、kernel 启动）与 CPU 完全不同。
